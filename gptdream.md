    I exercised the player’s discrete movement and follower system through a temporary runtime probe.
    
    Initial state:

    _direction_queue.append(Vector2i(signi(delta.x), signi(delta.z)))

    text
    Current behavior:
    replay the leader’s movement directions from the follower’s location
    
    Documented safety claim:
    retrace the exact cells already proven walkable by the leader

    The demo does not establish that invariant; it spawns the follower four movement steps away while trail_steps is two.

    continually pathfinding toward the leader. The issue is narrower: direction history does not prove cell history.

    - Queue absolute leader from_step/to_step positions.
    - Explicitly initialize the follower from a valid historical trail.

+
+Status: CONTRACT ONLY — IMPLEMENTATION NOT AUTHORIZED
+
+Version: 1.0
+
+Repository: `/mnt/data-drive/godot-dream`
+
+Milestone:
+
+```text
+Room A
+→ alter traveler state and Room A state
+→ cross a named exit
+→ arrive through a named entrance in Room B
+→ return through a named entrance in Room A
+→ the same traveler survives

+## 1. Purpose
+
+This contract defines the first boundary by which Dream stops being one scene containing mechanics and becomes a runtime capable of containing a world.
+
+The proof is deliberately limited to two small rooms and one in-process round trip:
+
+```text
+TEST ROOM A → TEST ROOM B → TEST ROOM A
+```
+
